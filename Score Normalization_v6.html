Score Normalization

Paste the raw judging export. This corrects for judges who score harsher or more generously than others by z-scoring each judge's Total scores, then rescales each application's corrected scores back onto its own raw-score range.

About this file — reuse it year over year ▸
This is a single HTML file with no installs, accounts, or internet connection required to run it — everything happens in the browser, and nothing you paste in ever leaves your machine or gets sent anywhere. Future organizing teams can reuse it by just opening the file (double-click it, or drag it into any browser tab). To hand it off: store it in the $100K shared drive or repo and share the file itself — anyone with a browser can run it, laptop or not, no MIT $100K account needed. If you want everyone on the team using the same copy without emailing files around, ask whoever manages your team's site/drive about hosting this HTML file at a stable link (e.g. GitHub Pages) — no code changes needed, it works as-is.

Before trusting a set of rankings, review every flag on every application — don't just take the top-line Normalized score at face value. Click into each flagged row: outlier means a judge's score looks far out of line with that application's other reviewers and is worth a manual read of the comments; conflict — averaged means the same judge scored the same application twice with different numbers and the tool averaged them (double-click the judge's name to see the originals); duplicate row means an exact repeat that's being kept and counted (or removed, depending on the checkbox below); cutoff-sensitive means finalist status changes depending on Normalized vs. Standard scoring. Also keep both checkboxes in Step 2 — "Exclude unfinished" and "Remove exact duplicate rows" — turned on; they're on by default for a reason, and turning them off will pull incomplete or accidentally double-counted reviews back into the math.
